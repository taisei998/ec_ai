# 3モール自動化ロードマップ

Amazon・楽天市場・Yahoo!ショッピングの競合価格を、毎朝9時に自動取得して、
自社より安い競合が出たら通知する。そこまでの進め方。

## 何が変わるのか

| 今のアプリ | これから |
|---|---|
| 毎朝9時に自動で調査は走る | 毎朝9時に自動で調査 |
| 結果を**手でコピペ**しないと反映されない | **コピペ不要**。判定まで自動 |
| 画面を開くまで気づけない | 競合に負けていたら**通知が届く** |
| Amazonは「データ不足」になりがち | 3モールすべて**公式API**で安定 |

---

## 工程01：鍵をそろえる（アカウント所有者の作業・すべて無料）

APIを使うには「鍵」（IDやトークン）が必要。アカウント所有者しか取得できないため、
ここは本人が実施する必要がある。簡単な順に並べた。

### 1-A 楽天市場：アプリIDを取得
- 楽天ウェブサービスでアプリを1つ登録すると `applicationId` が発行される
- **アフィリエイト登録は不要**（`affiliateId` はオプションパラメータ）
- 目安10分・無料・難易度やさしい
- 3つの中で圧倒的に簡単なので、ここから始めるのが推奨

### 1-B Yahoo!ショッピング：アプリIDを取得し、商用利用を照会
- Yahoo!デベロッパーネットワークでアプリ登録 → `appid` を取得
- **注意**: Yahoo!のAPIは原則「非商用利用」が前提。企業の商用利用は個別に問い合わせて許可を得る必要がある
- 「自社商品の競合価格を社内でモニタリングする」用途で使えるか、問い合わせフォームから照会が必要
- 回答待ちが発生するので、**最初に投げておく**と待ち時間が無駄にならない

### 1-C Amazon：SP-APIの開発者登録
- Seller Central から「**自社利用のプライベートアプリ**」として開発者登録
- 自社アカウントに繋ぐだけの用途なので**第三者向けアプリの審査は不要**、**料金もかからない**
  - 2026年1月に予定されていた年額$1,400の課金は同年5月に完全撤回。そもそも自社利用は当初から対象外
- 最終的に `Client ID` / `Client Secret` / `Refresh Token` の3つを取得
- 目安30分〜1時間

### ⚠️ 鍵の取り扱い（最重要）

**取得した鍵を `shinshouhin-navi.html` に絶対に書き込まないこと。**
このリポジトリは GitHub で公開されており、GitHub Pages で配信されているため、
書き込むと世界中の誰でも読める状態になる。

鍵は `_ローカル専用（共有しない）/` に置く。このフォルダは `.gitignore` で除外済み。

## 工程02：仕組みをつくる（実装作業）

### 2-A 3モールから価格を取得する処理
- **楽天・Yahoo!**: キーワード検索 → 価格の安い順にソート、で取得できる
  - 楽天: `sort=+itemPrice` で昇順。`itemName` / `itemPrice` / `shopName` が取れる
  - Yahoo!: v3 `itemSearch`。レート制限は 1クエリ/秒
- **Amazon**: 2段階が必要
  1. `searchCatalogItems`（Catalog Items API v2022-04-01）でキーワードから ASIN を検索
     - 1リクエスト最大20件、40件/秒
     - **このAPIは価格を返さない**
  2. `getItemOffers`（Product Pricing API）で ASIN を指定し最安値・Buy Box価格・競合オファーを取得

### 2-B 毎朝9時の自動実行
- クラウド上の定期実行を設定。PCの電源が入っていなくても動く
- 既存の「毎朝9時のニュース調査」ルーティンと同じ仕組み
- ただし今回は結果の反映まで自動なので、コピペは発生しない

### 2-C 判定と通知
- 自社売価と競合最安値を比較。既存アプリと同じ4段階判定ロジックを使う
  - 🔴競合が下回る / 🟡同値で並走 / 🟢自社が最安 / ○データ不足
- 内容量が違う場合の単価換算も既存ロジックを流用
  （例：「500ml×45本 ¥2,240」vs「500ml×48本 ¥2,280」→ 1本あたりで比較すると競合が安い）
- **異常がない日は通知しない**。毎朝「問題なし」が届くと見なくなるため、🔴のときだけ通知

## 工程03：動かして育てる

### 3-A 監視商品の登録
- 商品名・内容量・自社売価・アラートキーワードの4項目
- 既存アプリの「進捗を保存」で出力したJSONをそのまま流用できる

### 3-B 精度確認（省略しないこと）
- **AmazonのAPIの検索結果の並び順は、実際のAmazon検索ページの順位と一致しない可能性がある**
  - `searchCatalogItems` はカタログ検索であり、広告・売れ筋を考慮した検索順位とは別物
- 「APIが出した競合」と「実際に検索して出てくる競合」がずれていないか、
  最初の数日は目視で確認する。ずれていたら調整する

## 6モールの調査結果まとめ

| モール | 状況 | 今回の扱い |
|---|---|---|
| Amazon | 公式APIあり（SP-API・無料） | ✅ 自動化する |
| 楽天市場 | 公式APIあり（登録のみで使える） | ✅ 自動化する |
| Yahoo!ショッピング | 公式APIあり（商用利用の照会が必要） | ✅ 自動化する |
| au PAYマーケット | 商品検索の公開APIなし。バリューコマース（ASP）経由なら可能性あるが審査必要・用途がアフィリエイト向けでズレる | 手動チェックのまま |
| Qoo10 | 同上（出品者向けAPIは自社商品管理用のみ。競合検索不可） | 手動チェックのまま |
| カウシェ | 公開APIも商品検索連携もない。受注管理はCSV方式 | 手動チェックのみ |

3モールが安定してから、必要なら au PAY・Qoo10 を追加検討する。
いきなり6モール全部に広げると、どこで失敗しているか分からなくなる。

### スクレイピングは選択肢にしない
Amazon の利用規約は "any robot, spider, scraper, or other automated means" による
アクセスを明示的に禁止しており、公開されている価格情報でも対象。
自社が各モールの**出品者**でもあるため、出品者アカウント停止のリスクに直結する。

## 既存アプリはどうなるか

**消さずに残す。** 新しい自動監視は通知に特化させ、既存アプリは以下の用途で継続利用する。

- AIリサーチで売価を決める
- 業界ニュースを読む
- 履歴を振り返る
- 自動化できない3モール（au PAY・Qoo10・カウシェ）の手動チェック
