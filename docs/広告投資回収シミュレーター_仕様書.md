# 広告投資回収シミュレーター 機能仕様書

「新商品開発ナビ」内の既存機能「📈 広告シミュ」(`state.adSim`)を、**本仕様の内容に全面的に
作り直す**。既存の週次52週・bull/base/bearシナリオ・オーガニック流入加算の仕組みは廃止し、
月次3ヶ月固定・単一シナリオのシンプルな設計に置き換える。

## 0. 既存実装との関係(重要)

- 対象は既存の `state.adSim`(データモデルは `HANDOFF.md`の「データモデル state.adSim」節、
  UIは下部ナビ「📈 広告シミュ」)。**これを本仕様の内容で置き換える。**
- **既存の登録データ(`portfolios[]`)は移行不要。リセットして良い。** 過去データの互換変換
  ロジックは実装しなくてよい。
- 廃止する要素:週次52週構造、`weekOverrides`(週次ピン留め)、`scenarios:{bull,base,bear}`、
  `monthly[].organic`(自然流入の直接加算)。
- 維持・踏襲してよい既存資産:単一HTMLファイル・ES5スタイルという実装方針そのもの、
  `renderAirChart()`と同じSVG自作によるグラフ描画idiom、永続化の配線パターン(後述)。

## 1. 目的・背景

注力商品(親ASIN単位)に対して、赤字を出してでも先行して広告投資を行う際、
「どこまで投下し、いつ回収できるか」を月次でシミュレーションするツール。

シミュレーション結果は、上長への説明・承認が必要な特別枠投資(通常の運用予算を超える先行投資)の
判断材料として使用する。共有は画面表示・スクリーンショットで完結させる想定で、PPTX/PDF出力は不要。

## 2. 対象範囲(v1)

- 対象は**親ASIN単位**。子ASINが複数ある場合は、想定販売比率で加重平均して
  1つの経済性(単価・原価・手数料・粗利)にまとめて扱う。
- シミュレーション期間は**3ヶ月固定**(既存の週次52週から変更)。
- シナリオは**単一(基本ケースのみ)**。bull/base/bearの複数シナリオ切替は実装しない。
- プラットフォームは**Amazon限定**(将来的に他プラットフォームへの拡張を見据えるが、v1はAmazonのみ)。

## 3. データモデル(商品マスタ)

商品マスタは複数の親ASINを登録できる本格的なマスタとし、**ブラウザに保存**して永続化する。

```
親ASIN
├─ 商品名
├─ 目標粗利率(%)      ※黄字/黒字の境目。親ASINごとに個別設定
├─ 最大許容粗利率(%)  ※赤字/許容外の境目。未入力可(未入力なら許容外判定なし)
└─ 子ASIN(複数登録可)
    ├─ 商品名/SKU名
    ├─ 売価(円)
    ├─ 原価(円)
    ├─ Amazon手数料(円/点、固定額)
    ├─ コンサル手数料(円/点、固定額)   ※既存の consultPct(%・ポートフォリオ単位)は廃止し、
    │                                    子ASINごとの円額固定に統一する
    └─ 想定販売比率(%)  ※子ASIN間の合計が100%になるように入力
```

### 加重平均の算出(親ASIN選択時に自動計算)

```
加重平均単価      = Σ( 子ASINの売価 × 想定販売比率 )
加重平均1点純粗利 = Σ( (子ASINの売価 − 原価 − Amazon手数料 − コンサル手数料) × 想定販売比率 )
```

## 4. シミュレーション入力

親ASINを選択した上で、以下を入力する。

| 項目 | 説明 |
|---|---|
| CPC(円) | 実績値をAmazon広告画面を見ながら手入力。3ヶ月を通じて固定値として扱う(上振れ調整はv1では実装しない) |
| CVR(%) | 実績値を手入力。3ヶ月を通じて固定値として扱う |
| 月1投下広告費(円) | 自由入力 |
| 月2投下広告費(円) | 自由入力 |
| 月3投下広告費(円) | 自由入力 |

投下額は「逓減型」を想定した使い方(月1・2を厚め、月3で絞る)だが、
具体的な配分比率は毎回ユーザーが自由に入力する。固定の逓減計算式は組み込まない。

### パターン保存・比較

- 同一の親ASINに対して、**2〜3パターン**の投下シナリオ(CPC/CVR/月別投下額の組み合わせ)を
  保存し、並べて比較できるようにする。
- 各パターンには名前を付けられるようにする(例:「積極型」「慎重型」)。
- ※これは既存の`scenarios:{bull,base,bear}`(前提の強気/慎重を切り替えるもの)とは別物。
  こちらはユーザーが投下額配分を変えて試す「what-ifパターン」の保存・比較。

## 5. 計算ロジック(月次、各パターンごとに算出)

```
① クリック数   = 広告費 ÷ CPC
② 販売点数     = クリック数 × CVR
③ 売上         = 販売点数 × 加重平均単価
④ 月次粗利     = 販売点数 × 加重平均1点純粗利
⑤ 月次損益     = 月次粗利 − 広告費
⑥ 月次実質粗利率 = 月次損益 ÷ 売上 × 100
⑦ 累積損益     = 当月までの月次損益の合計
```

## 6. 判定ロジック

### 単月ステータス(2つのしきい値で4段階)

**※2026年9月7日に改訂。** 当初は「0%未満＝赤字/0%〜目標＝黄字/目標以上＝黒字」の3段階と、
別建ての「最大許容累積赤字額(円)」によるガードレール警告だったが、ガードレールを
**「最大許容粗利率(%)」**に変更し、単月判定そのものに組み込んで4段階にした。

`最大許容粗利率` は「赤字をどこまで許容するか」の下限、`目標粗利率` は「黄字/黒字」の境目。
例: 最大許容粗利率 -20% / 目標粗利率 13% のとき

| 条件 | ステータス | 表示色の目安 |
|---|---|---|
| 月次実質粗利率 < 最大許容粗利率 (-20%未満) | 許容外(警告対象) | 赤(反転) |
| 最大許容粗利率 ≦ 月次実質粗利率 < 0% (-20%〜0%未満) | 赤字 | 赤 |
| 0% ≦ 月次実質粗利率 < 目標粗利率 (0%〜13%未満) | 黄字 | 黄 |
| 月次実質粗利率 ≧ 目標粗利率 (13%以上) | 黒字 | 黒(または緑) |

- 判定は**先に「許容外」を評価する**。最大許容粗利率にプラス値を入れた場合
  (＝最低これだけは粗利率が欲しい、という使い方)でも矛盾なく判定できる。
- 最大許容粗利率は**未入力可**。未入力なら許容外判定を行わない(＝従来の3段階と同じ挙動)。
  **0%は「赤字を一切許容しない」という有効な設定**として扱う。
- 判定は**表示と同じ小数第1位に丸めた値**で行う(表示13.0%・目標13%なのに黄字、という
  食い違いを防ぐため)。
- 最大許容粗利率は目標粗利率以下であること(上回ると「目標達成なのに許容外」という矛盾)。

### 回収判定

- 3ヶ月目終了時点で**累積損益がプラスに転換しているか**を判定し、明示する。
- 3ヶ月で転換しなかった場合は「未回収」とだけ表示する(延長予測はv1では実装しない)。

### ガードレール(投下上限)

- 上記の「許容外」判定がガードレールを兼ねる。許容外の月が1つでもあるパターンには
  警告表示を出す(このしきい値自体は経営判断で決まるものなので、ツール側は入力値として
  受け取るのみでよい)。仕様上は「月1・月2時点」だが、月3が谷になる入力もあり得るため
  **3ヶ月すべてを判定対象にしている**(見逃しを防ぐための上位互換)。
- 円建ての累積損益グラフには上限ラインを引かない。率のしきい値は売上に比例した
  「傾きのある境界」になり固定の水平線にならないため、警告は表・警告ボックスで示す。

## 7. 出力・UI要件

- **単月損益の推移表示**:月1〜3を、赤字/黄字/黒字で色分けして一覧表示。
- **累積損益グラフ**:横軸を月1〜3とし、選択した2〜3パターンを重ねて表示する折れ線グラフ。
  既存の`renderAirChart()`と同じ「SVG文字列を組み立ててinnerHTML」idiomを踏襲する
  (Recharts/React等は導入しない。理由はHANDOFF.md「採用しなかった案:Recharts」参照)。
- **パターン別サマリー表**:各パターンについて「総投下額」「3ヶ月目時点の累積損益」
  「黒字転換の有無」を横並びで比較できる表。
- 上記のグラフ+表は両方表示する(どちらか一方に絞らない)。

## 8. スコープ外(v1では実装しない)

- CPCの上振れ効果(投下額を増やすとCPCが上がりやすい、という動的調整)
- リピート購入を含めた回収計算(初回購入ベースのみで計算する)
- クーポン・値引きなどの販促費(広告費以外の投資額は含めない)
- 下振れシナリオ(bull/base/bear等の悲観ケース比較。既存機能にあったが今回は廃止)
- オーガニック流入への影響(カニバリゼーション)の考慮。既存の`monthly.organic`直接加算方式も廃止
- 週次粒度・週次ピン留め(既存の`weekOverrides`は廃止、月次のみ)
- 在庫制約のチェック
- 3ヶ月で回収できなかった場合の延長予測
- Amazon以外のプラットフォーム対応
- PPTX/PDF/Excel等への出力機能

## 9. 実装上の技術要件(HANDOFF.mdより、必ず遵守)

- **単一HTMLファイル**:`shinshouhin-navi.html`のみを編集する。`<script src>`・`<link>`は
  一切追加しない(CDN依存を増やさない)。ビルド工程なし。
- **JSはES5スタイルで統一**:`var`/`function`のみ。アロー関数・テンプレートリテラルは
  既存コードに1つも使われていないため、新規コードも合わせる。
- **CSS変数は`.viz-root`配下で定義**(`:root`ではない)。新しいマークアップは`.viz-root`
  配下(`<div class="app">`)に置かないと`var(--...)`が解決しない。
- **永続化の配線(6点セット)を必ず全て通すこと**:初期state定義 / `adSimEnsureState()`(相当の
  ensure関数)/ `syncBuildPayload()` / `syncApplyRemote()` / `#importFile`(インポート処理)/
  `markDirty()`。**この配線を1つでも忘れるとリロードでデータが消える。**
  (`priceWatch`・旧`adSim`と同じ「配列でなければ空配列にフォールバック」パターンを踏襲)
- **`attr()`の既知の落とし穴**:`attr(0)`は`""`を返す(`v||""`のため)。数値をvalue属性に
  入れるときは`attr(String(n))`を通すこと。通さないと0の項目が空欄で描画される。
- **フォーカス飛び対策**:値の入力中はテーブルを再描画しない。`input`イベントでは
  バリデーション表示とボタンの`disabled`だけ更新し、テーブルの`innerHTML`再構築は
  構造が変わったとき(ポートフォリオ切替・行の追加削除)に限定する。
- **バリデーション**:想定販売比率の合計は100.0%必須(判定・表示時のみ小数第1位に丸め、
  内部値は丸めない。浮動小数点誤差で正しい入力が弾かれるのを防ぐため)。エラーが1件でも
  あれば「計算実行」「パターン保存」を両方disabledにする。
- **グラフの3状態**:①未計算=空枠に「パラメータを入力してください」②正常=描画
  ③エラー=直前の結果を凍結表示した上で半透明オーバーレイ+エラー解消を促す表示
  (既存の設計思想を踏襲)。
- 検証は`HANDOFF.md`「開発・検証の進め方」の手順(`node --check`相当の構文チェック→
  Playwrightでのheadlessブラウザ検証)に従うこと。
